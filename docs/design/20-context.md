# 上下文与提示词详细设计

> **本文档职责**：回答「AI 上下文怎么组织、提示词分几层、项目规则从哪来」——分层策略、三层注入、AGENTS.md 通道的约束与理由。
> 实现契约（注入代码、端点）见 `docs/api/10-api-project.md`（AGENTS.md 读写端点）与 `docs/api/80-api-chat.md`（chat 请求体 context 字段）；内核提示词实现见 `packages/agent/src/prompts.ts`。
> 已过时/被修订决策的完整历史原文可由 `git log` 回溯，本文档只收录**仍生效**的契约。

## 1. 分层上下文策略

**不把整个世界塞进 prompt**。四级分层，每层职责与预算不同：

| 层 | 内容 | 预算特征 |
| :--- | :--- | :--- |
| 系统指令 | 固定：AI 角色定义 + 行为规范 | 稳定基线 |
| 聚焦上下文 | 动态：当前视图中的实体 + 紧邻关系（focus context） | 有限、明确 |
| 扩展上下文 | AI 通过工具调用**按需拉取** | 按需膨胀、可裁剪 |
| 对话历史 | 滑动窗口（配对块同裁同留） | 有上限 |

**预算数值与来源**（具体值不在本文档写死——以代码常量为准，本文只登记口径）：

| 层 | 口径 | 可配置 |
| :--- | :--- | :--- |
| 系统指令 | 固定预算；超限**仅记录不裁剪**（用户内容不可裁） | 否 |
| 聚焦上下文 | 固定预算；超限截断 + 显式告知 | 否 |
| 工具清单 | 独立计，**不参与裁剪**（模型必须看到完整工具表） | 否 |
| 对话历史 | **激活模型 `contextWindow` × `context_budget.history_ratio`**，并经总闸 clamp | 是（用户级 `config.json`） |
| 单条工具结果 | `context_budget.tool_result_max_tokens`：超限截断 + 结构化提示（模型必须知道数据不完整） | 是 |

**不变式**：

- **裁剪不得裁空**：预算放不下任何块时，从尾部按配对块累积、直到喂回 payload 非空（宁可略超预算，不可发一个没有历史的请求）。**前提**：历史本身含至少一条 `user` 消息（`buildContext` 的调用前置条件）——历史一条 user 都没有（如仅孤立 assistant）时末条约束会剥空 payload，属调用方输入错误，不属裁剪问题。
- **总闸高于历史预算**：总闸 = `contextWindow × 0.5`（不可配）；历史预算被 clamp 到「总闸 − 余量」并记日志——历史预算配得过大只应降级，不得把对话打断。
- **估算器是分级启发式**（ASCII 4 字符 ≈ 1 token；非 ASCII / 中文 ≈ 1.7 字符 ≈ 1 token，即 1 汉字 ≈ 0.6 token，误差约 ±20%）：预算数字是**护栏不是精确计量**（真值以 provider 返回的 usage 为准，仅作为历史基线与占用条分子）；裁剪决策宁可保守。
- **占用条口径**：前端占用条分母 = `done` 帧的 `context_budget.total`（本轮生效预算），不是模型窗口（1M 窗口下占比会显得永远为空，是假指标）。

**usage 基线不变式**：预算计算**优先采用「最近一次成功响应的真实 usage」**，其后消息按分级密度估算（口径见 §1「预算数值与来源」）；**裁剪/重排历史后必须重置 usage 基线**——旧 usage 描述的是裁剪前的前缀，直接沿用会导致预算漂移。

**为什么**：模型上下文窗口有限，全量注入必然超限；分层让「当前关注什么」由用户/页面决定、「还要什么」由 AI 自己按需拉取，预算始终受控。

## 2. 提示词三层注入

最终 Prompt = 三层拼接，**编辑者与持久化各不相同，注入逻辑保持分层，不搞双通道漂移**：

| 层 | 编辑者 | 持久化 | 示例 |
| :--- | :--- | :--- | :--- |
| 内核提示词 | 开发者 | 代码固定（`agent/prompts.ts`） | 「你是创作顾问，不生成正文」 |
| 项目设定 | 用户 | 项目目录 AGENTS.md（§3） | 「力量体系：练气→筑基→金丹」 |
| 临时指令 | 用户 | 不持久化（聊天框即时输入） | 「今天只讨论第三卷」 |

**不变式**：项目设定只有 AGENTS.md 一个持久化通道（`project.json` 的 `prompt` 字段已废弃，见 §3）；聊天框消息即临时指令层，不单独设字段——避免两套注入通道并存漂移。

## 3. 项目规则文件 AGENTS.md

项目目录 **AGENTS.md** 是**唯一**持久化上下文通道，取代原 project.json `prompt` 字段：

- **自动迁移**：打开项目时若 `prompt` 存在且无 AGENTS.md → 自动迁移写入 AGENTS.md（内容原样，一次迁移后 prompt 不再使用）。
- **注入**：system「## 项目设定」段数据源 = AGENTS.md 文件内容。
- **编辑通道**：设置页直编（GET/PUT `/project/agents`，原子写）+ 用户可在文件管理器中直接编辑（web 读取 mtime 检测外部修改，提示刷新/重新加载）。
- **为什么**：AGENTS.md 是社区广泛接受的「项目规则」惯例，可见、可版本化；prompt 字段藏于 project.json 不可见不可控。
