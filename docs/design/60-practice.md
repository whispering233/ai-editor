# 作家文风练习详细设计（2026-10 改版）

> **本文档职责**：回答「练什么、一个工作区等于什么、预置素材从哪来、数据长什么样、AI 能做什么不能做什么、点评怎么产出与回溯、上下文注入了什么」。工作区抽象见 `00-master-design.md` 与 `architecture.md`；表字段见 `../db/schema.md`；端点见 `../api/120-api-practice.md`；工具见 `../api/tool-calling.md`；页面视觉见 `../ui/DESIGN.md`。

## 1. 定位与边界

作家文风练习是**独立工作区**（`kind = "practice"`）：围绕**一位预置作家**，对照范文仿写或按题目自由写作，AI 逐维度点评。它是**技艺练习**，不是作品生产。

| 边界 | 口径 |
| :--- | :--- |
| **练习稿 ≠ 作品正文** | 练习工作区独立于小说：不参与大纲、不产生 Delta、不进关系表、不出现在小说导出里。正文边界（见 `00-master-design.md`）是小说工作区的口径 |
| **AI 不代写** | 练习区 AI 的工具面**不存在任何能写用户稿件的工具**；它只能读范文 / 稿件 / 风格说明、写自己的产出（点评卡、题目） |
| **不预置作品正文** | 产品**不内置任何作家作品的正文文本**（版权）。预置的只有：作家介绍、作品清单与作品介绍、作家风格说明 |
| **不校验文本归属** | 产品**不校验**用户导入的文本是否真的属于所选作品 / 该作家——这超出本产品范围。选哪部作品由用户决定，下拉里也有「其他」兜底 |
| **范文 = 纯文本快照** | 样本是「给练习提供对照」的纯文本，不产出任何结构化创作要素、不要求模型理解整本——与被移除的「拆解小说」管线不是同一件事 |
| **单稿** | 一次练习 = 一份稿件（可覆盖重写）；多稿历史不在 MVP（见 `backlog.md`） |

## 2. 工作区单位：一位作家 = 一个工作区

| 项 | 口径 |
| :--- | :--- |
| 单位 | `practice/<作家名>/`，`project.json` 带 `author_id`（预置作家 id） |
| 作家来源 | **产品预置，不可新建**（清单 = shared 常量表 `AUTHOR_CATALOG`）；根首页练习分区列出全部预置作家卡（未开始的也列） |
| 懒创建 | 点未开始的卡片 → 建三文件 + 写 `author_id` + `name` = 作家名（复用 `POST /project/create`，新增 `author_id` 入参）；已存在 → 直接打开 |
| 落点 | 打开后落 `#/practice`（核心动作是练，不落介绍页） |
| 重命名 | **不提供**（名字 = 作家名；改名会与预置清单脱钩） |
| 删除 | 保留（复用 `POST /project/delete` 与云端前置推送口径），删后卡片回到「未开始」= **用户的重置手段** |
| 存量隔离 | `author_id` 缺失 / 未知的练习工作区（旧模型遗留、预置作家被移除）**不在根首页列出**（目录留盘、备份包与云端份不受影响）；其端点访问 → 400 `VALIDATION_ERROR`（文案「练习工作区未关联预置作家」）。**不做名字认领 / 不做旧数据迁移** |
| 周边管道 | 备份 / 恢复 / 云端 / 导入导出**沿用 `project` 模块既有管道**（三文件包；备份文件名统计段自然为 `0-0-0`）；`kind` 校验口径不变（覆盖类写包入口 `KIND_MISMATCH`） |

## 3. 预置素材：三件 + 一个可替换的素材包

| 素材 | 载体 | 用户可否修改 |
| :--- | :--- | :--- |
| 作家介绍 | shared 常量（markdown 字符串） | **否**（只读） |
| 作品清单（id / 中文名 / 介绍） | shared 常量（结构化数组，封闭集合） | **否**（不可增删改） |
| 作家风格说明 | shared 常量（markdown）+ 用户覆盖落 `data.db` | **是**：编辑 / 用 `.md` 替换 / 恢复预置 |

**为什么预置文本放 shared 常量而不是文件资产**：`server` 包发布面只有 `dist` + `client-dist`、`shared` 只发 `dist`——做成「文件资产」要同时改 npm 发布、构建复制、桌面版 `pnpm deploy` 三处，漏一处就是打包态缺内容。常量还让**客户端页面、作品下拉、AI 工具读同一份**（单源），且新增作家 = 新增一个文件 + 清单一行，无迁移。

**风格说明 = 素材包（预留结构化扩展）**：

- 读 = 用户值 **`??`** 预置值（`GET /practice/style-pack` 同时回 `customized` 布尔）；写 = `PUT`（非空、上限常量）；恢复 = `DELETE`（幂等，没有用户值也 200）。
- 存储 = `data.db` 专属表 `practice_style_packs`（**必须进三文件**，否则备份 / 云端 / 导出 / 恢复都不继承它）。
- **结构化预留 = 不建空列**：将来的 NLP 统计（词频 / 句长分布 / 用词风格等）以**后续迁移加列或加表**接入，读写仍走同一处（db helper + 端点）。现在留 `extra` 空列 = 死重（YAGNI）。
- 页面按 **markdown 渲染**（`@ant-design/x-markdown`，与聊天同款组件）；编辑 = `Input.TextArea` 存 md 源码；**不引块编辑器**（块文档的真相是块 JSON，服务端不解析块结构 ⇒ AI 读不到文本，且 md 往返有损）。

**作品清单是封闭集合**：样本的「关联作品」下拉 = 预置作品 + 末项「其他」（`work_id = null`）。未知 `work_id`（预置被移除）读侧按「其他」渲染。用户**不能自建作品**——「不校验归属」的诚实表达就是兜底桶，而不是再长一套增删改级联语义。

## 4. 练习的两种形态

| 形态 | 页面 | 依据 | 数据 |
| :--- | :--- | :--- | :--- |
| **仿写**（对照范文） | `#/practice` 列表 + `#/practice/:sampleId` | 范文样本 + 作家风格说明（可按需参考） | `practice_samples`（样本挂作品） |
| **自由练习**（按题目） | `#/free` 列表 + `#/free/:pieceId` | **作家风格说明（唯一依据）** | `practice_free_pieces` |

**流程（仿写）**：新建样本（选关联作品 + 可选片段说明 + 范文文本，可导入文件或粘贴）→ 写稿 → 保存 → 「让 AI 点评」→ 对照点评重写 → 再点评（覆盖同一份稿件与同一张卡）。

**流程（自由练习）**：

| 步 | 动作 | 谁做 |
| :--- | :--- | :--- |
| 1 | 新建题目（题目 + 可选写作要求，`topic_source = "user"`） | 用户 |
| 1' | 或「让 AI 出题」：先建**空题行**（`topic_source = "ai"`）→ 发一条普通用户消息触发 | 用户 |
| 1'' | AI 经 `submit_practice_topic` 写 `topic` + `brief`（**题目非空则抛错拒写**，防覆盖） | AI |
| 2 | 写稿（纯文本）→ 保存 | 用户 |
| 3 | 「让 AI 点评」→ AI 读风格说明与稿件（只读工具）→ 提交点评卡 | 用户 / AI |
| 4 | 不满意 AI 出的题 → **删掉该篇重新建**（不做覆盖式「换一题」） | 用户 |

自由练习**篇数不限**，多篇并存、互不覆盖；「让 AI 出题」与「新建题目」都只是新增一行。

## 5. 数据模型

| 概念 | 承载 | 语义 |
| :--- | :--- | :--- |
| 范文样本 | `practice_samples` | 一份范文快照（`text`，**不可变**）+ `work_id`（可空 = 其他）/ `excerpt_label`（片段说明，空串 = 未填）+ 一份用户稿（`draft`）+ 一张点评卡（`feedback`） |
| 自由练习篇 | `practice_free_pieces` | 题目（`topic`，空串 = 待出题）+ 写作要求（`brief`，空串 = 无）+ 题目来源（`topic_source`）+ `draft` + `feedback` |
| 风格说明素材包 | `practice_style_packs` | 用户对某作家的风格说明覆盖（`author_id` 主键 + `content`） |

字段契约（含长度上限常量）见 `../db/schema.md`；删除 = **物理删**（练习数据无回收站：回收站是小说语义，联动大纲节点与实体）。

**不改的三条硬不变式**：范文快照不可变；用户稿唯一写入口 = `PUT /practice/samples/:id` / `PUT /practice/free/:id`（AI 工具面无写稿工具）；`feedback` 只由提交工具写。

## 6. 点评卡（结构化产出）

「点评」不是自由回答，而是一次**结构化产出**：每个维度给出「依据特征 / 你的写法 / 证据引用 / 建议」。

| 字段 | 含义 |
| :--- | :--- |
| `dimensions[]` | 维度数组（**由 AI 从依据中提炼**，不是固定清单） |
| `dimensions[].name` | 维度名（如「句长节奏」「叙述距离」） |
| `dimensions[].sample_trait` / `draft_trait` | 依据侧 / 你的稿在该维度上的表现 |
| `dimensions[].sample_quotes[]` / `draft_quotes[]` | **证据引用**（依据原句 / 你的原句） |
| `dimensions[].advice` | 可执行建议 |
| `summary` | 一句话总评（可选） |

**卡体形状两种练习完全同形**（同一份 schema 常量、同一个前端卡面组件），差别只在**引用校验源**与**页面标签**：

| 练习 | `sample_*` 语义 | 引用校验 |
| :--- | :--- | :--- |
| 仿写 | 范文样本 | 每条 `sample_quotes` ⊆ 范文 `text`；`draft_quotes` ⊆ `draft` |
| 自由练习 | 作家风格说明 | 每条 `sample_quotes` ⊆ 风格说明（用户值 `??` 预置）；`draft_quotes` ⊆ `draft` |

### 两条硬规则

1. **引用必须可回溯**：由服务端在写入前校验子串关系；不匹配的引用**直接丢弃**（不阻断卡片、不重试），并计入 `dropped_quotes`。**空串与纯空白不算有效引用**（数学上它们是任意字符串的子串），走同一条丢弃路径。
2. **提交通道 = 工具**：点评经提交工具写入（只写 `feedback` 字段）。工具集里**没有任何工具能写 `draft`**。
   > 边界一句话：**AI 能写它自己的产出，不能写用户的产出。**

**维度数上限 = 常量 `MAX_FEEDBACK_DIMENSIONS`**（唯一出处；工具说明由该常量插值生成，禁止复述数字）。

**为什么维度由 AI 提炼而不是固定清单**：固定清单是为「跨练习统计」提前建结构——那个需求未成立（YAGNI）；维度以文本快照留在卡里，不建 schema。

## 7. AI 边界：结构级与 prompt 级

| 层 | 约束 | 强度 |
| :--- | :--- | :--- |
| **工具面** | 练习工作区只注册**四个只读工具 + 三个写自己产出的工具**（见下表）；小说工具与**提案工具一律不注册** | **结构性**（靠 `scope` 注册过滤，不靠提示词） |
| **稿件写入** | 工具面没有写稿工具 ⇒ AI 改不了用户稿 | **结构性** |
| **出题守卫** | `submit_practice_topic` 在题目非空时**抛错**（拒写） | **结构性** |
| **自由对话** | 聊天里**不禁止**出现示范句（问答式是产品四大原则之一：「这句为什么好？」） | **prompt 级**（必须在文档里写明它不是结构级保证） |

七件工具（定义见 `../api/tool-calling.md`；装配层按 `kind` 过滤，单点 = `tools` 注册表）：

| 工具 | 读写 |
| :--- | :--- |
| `get_practice_sample` | 只读：范文（分页） |
| `get_practice_draft` | 只读：仿写稿（分页） |
| `get_free_draft` | 只读：自由练习稿（分页）——刻意不做「一个工具 + 多态 id」：两表语义与引用校验源不同 |
| `get_style_notes` | 只读：作家风格说明（分页） |
| `submit_style_feedback` | 写 `practice_samples.feedback` |
| `submit_free_feedback` | 写 `practice_free_pieces.feedback` |
| `submit_practice_topic` | 写 `practice_free_pieces.topic` / `brief` |

**点评与聊天是两条路径**：点评走结构化工具产出（卡片），自由问答走普通对话；两者落在**同一个工作区会话**里。点评 / 出题触发 = 一条真实的用户消息（透明、可回溯，不引入隐藏语义）。

**仿写点评与风格说明的关系**：仿写以**范文为对照基准**，风格说明是**可按需读的背景知识**（`get_style_notes`），不作强制引用源——硬塞会把「这一段像不像」稀释成泛泛的风格描述；自由练习则以风格说明为**唯一依据**。

## 8. 上下文注入

触发点评 / 出题时，客户端**只发** `context.practice_sample_id` 或 `context.practice_free_piece_id`；服务端**现读**数据库展开本轮注入（与「推演节点只发布尔、服务端现读 `project.json`」同款）：

| 触发 | 注入项（**只给事实**） |
| :--- | :--- |
| 仿写点评 | 样本 id + 作家名 + 作品名（「其他」按兜底文案）+ 片段说明（空则不注入该行） |
| 自由练习出题 / 点评 | 篇 id + 作家名 + 题目（空题行 = 说明这是待出题的新篇）+ 写作要求（空则不注入该行） |

「必须提交点评卡 / 出题要给写作要求」这类**指令语义唯一出处 = 练习内核提示词常量**（agent 包 `PRACTICE_KERNEL_PROMPT`）——注入段不复述，否则 = 第二事实源。

**刻意不注入范文、稿件与风格说明全文**：它们走只读工具分页读取（受单条工具结果上限与续读提示保护），避免每轮上下文膨胀——与小说侧「聚焦章只注入标题 + 摘要 + 节选、正文按需拉取」同一口径。**不接受客户端传入的观察 / 文本**（否则是任意上下文注入）。

## 9. 界面与路由（视觉契约见 `../ui/DESIGN.md`）

| 面 | 路由 |
| :--- | :--- |
| 作家介绍（只读） | `#/author` |
| 作品介绍（只读，作品列表 + 介绍） | `#/works` |
| 作家风格说明（渲染 + 编辑 / 导入 `.md` / 恢复预置） | `#/style` |
| 文风练习（样本列表，按作品分组；详情 = 范文 → 我的稿 → 点评卡） | `#/practice`、`#/practice/:sampleId` |
| 自由练习（题目列表；详情 = 题目 → 我的稿 → 点评卡） | `#/free`、`#/free/:pieceId` |

**左栏五项**（顺序 = 上表自上而下）；顶部标识仍是「文风练习」（分区身份，回根首页 `#/`），作家名走 InfoBar 项目名与各页标题。**路由守卫**：练习专属首段清单是**单一常量**（`author` / `works` / `style` / `practice` / `free`）——练习工作区按允许清单放行，小说工作区挡任一段（保住 fail-closed：新增练习页不会漏挡）。

## 10. 不变式汇总

1. 练习数据只活在**练习工作区**的专属表里；不写小说语义的表，不进回收站（物理删）。
2. 一个工作区 = 一位预置作家（`author_id`）；作家不可新建、不可重命名，删除 = 重置。
3. 预置素材（作家介绍 / 作品清单 / 风格说明）是 shared 常量；只有风格说明可被用户覆盖，且覆盖进三文件（备份 / 云端 / 导出自动继承）。
4. 范文快照不可变；用户稿只有用户能写；点评卡与题目只由对应工具写。
5. 点评卡的引用必须能在**该练习的依据**（范文 或 风格说明）或用户稿件里逐字找到，否则丢弃。
6. 练习工作区不注册小说工具与提案工具（结构性）；出题工具拒写已有题目。
7. 触发点评 / 出题的注入由服务端现读展开，客户端只发 id。
8. 点评 / 出题留痕在会话历史里（用户可见那条消息），卡片与题目本身从数据库读（刷新后仍在）。

## 11. 升级路径（未排期）
