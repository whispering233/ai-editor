# 文风仿写练习详细设计（2026-10）

> **本文档职责**：回答「练习练什么、数据长什么样、AI 能做什么不能做什么、点评怎么产出与回溯、上下文注入了什么」。工作区抽象见 `00-master-design.md` 与 `architecture.md`；表字段见 `../db/schema.md`；端点见 `../api/120-api-practice.md`；工具见 `../api/tool-calling.md`；页面视觉见 `../ui/DESIGN.md`。

## 1. 定位与边界

文风仿写练习是**独立工作区**（`kind = "practice"`）：用户给一段范文，自己写一段仿写，AI 逐维度对照点评。它是**技艺练习**，不是作品生产。

| 边界 | 口径 |
| :--- | :--- |
| **练习稿 ≠ 作品正文** | 练习工作区独立于小说：不参与大纲、不产生 Delta、不进关系表、不出现在小说导出里。正文边界（见 `00-master-design.md`）是小说工作区的口径 |
| **AI 不代写** | 练习区 AI 的工具面**不存在任何能写用户稿件的工具**；它只能读样本与稿件、并提交自己的点评 |
| **导入范本 ≠ 批量拆解** | 范本是**纯文本快照**，用途是「给练习提供样本」；不产出任何结构化创作要素、不要求模型理解整本——与被移除的「拆解小说」管线（LLM 整本抽取结构化 JSON）不是同一件事 |
| **单稿** | 一次练习 = 一份稿件（可覆盖重写）；多稿历史不在 MVP（见 `backlog.md`） |

## 2. 流程

| 步 | 动作 | 谁做 |
| :--- | :--- | :--- |
| 1 | 建「文风目标」（名字 + 用户自己的观察，可选），并在其下建「练习样本」：粘贴一段范文（短样本），填来源说明 | 用户 |
| 2 | 写仿写稿（纯文本） | 用户 |
| 3 | 点「让 AI 点评」→ 触发一轮对话（落在该工作区的会话历史里） | 用户 |
| 4 | AI 读范文与稿件（只读工具），提交**点评卡**（结构化产出，见 §4） | AI |
| 5 | 对照点评重写 → 再点评（覆盖同一份稿件与同一张卡） | 用户 / AI |

**范文来源（MVP）**：只有**粘贴**一种。跨工作区取用（从某本书的章正文或参考资料快照进练习）受「服务端同一时刻只打开一个工作区」约束，且需要「在书里选中 → 送进练习」的动作链，**留作升级路径**（见 `backlog.md`）。来源说明（`source_label`）由用户手填（如「汪曾祺《受戒》节选」），恒有——列表要展示它。

**范文是快照**：落库后不可变。练习工作区与书互相独立，实时引用做不到也不该做（原文被改/删会让练习悬空）。

## 3. 数据模型

| 概念 | 承载 | 语义 |
| :--- | :--- | :--- |
| 文风目标 | `practice_targets` | 「要模仿的文风」：`name` + `observation`（**用户自己观察到的文风特点**，可选） |
| 练习样本 | `practice_samples` | 一份范文快照（`text`，不可变）+ 一份用户稿（`draft`）+ 一张点评卡（`feedback`） |

一个目标挂 N 个样本（同一文风可练多段）。**MVP 是 1 样本 : 1 稿件**（`draft`/`feedback` 与样本同行）——多稿历史届时拆独立表（升级路径，见 `backlog.md`）。

字段契约（含长度上限常量）见 `../db/schema.md`；删除 = 物理删（练习数据无回收站：回收站是小说语义，联动大纲节点与实体）。

**周边管道零新增**：练习工作区的备份 / 恢复 / 云端 / 重命名 / 导入导出**沿用 `project` 模块的既有管道**（备份包 = 三文件；备份文件名格式不变——统计段在练习工作区自然为 `0-0-0`，不做特殊分支；**新建**导入按包内 `kind` 落回对应目录；云端目录名仍为 `<名字>-<id>`，按 id 区分）。**例外只有一处校验**（2026-10 裁定）：**写包进已存在工作区的三个入口**（`POST /project/backup/restore`、`POST /cloud/pull`、`POST /project/import` 的 id 命中覆盖恢复）在写盘前比较「包内 `kind`（缺失/未知 → `novel`）」与「目标工作区 `kind`」，不等 → 400 `KIND_MISMATCH`（**不动三文件内容**）——旧包（`kind` 引入前只存在小说工作区）⇒ 缺字段即小说包，在小说工作区正常恢复（并补写 `kind: "novel"`），在练习工作区被拒；**新建入口**（import id 不命中 / `cloud/import-book`）无目标可比，仍按包内 `kind` 落目录。

## 4. 点评卡（结构化产出）

「点评」不是自由回答，而是一次**结构化产出**：每个维度给出「范文特征 / 你的写法 / 证据引用 / 建议」。

| 字段 | 含义 |
| :--- | :--- |
| `dimensions[]` | 维度数组（**由 AI 从范文提炼**，不是固定清单） |
| `dimensions[].name` | 维度名（如「句长节奏」「叙述距离」） |
| `dimensions[].sample_trait` / `draft_trait` | 范文 / 你的稿在该维度上的表现 |
| `dimensions[].sample_quotes[]` / `draft_quotes[]` | **证据引用**（范文原句 / 你的原句） |
| `dimensions[].advice` | 可执行建议 |
| `summary` | 一句话总评（可选） |

**刻意没有「示范」字段**：模型没有位置放成段文字 ⇒ 卡片永远是诊断，不会变成代笔。

### 两条硬规则

1. **引用必须可回溯**：每条 quote 必须是范文 `text` 或用户稿 `draft` 的**子串**，由服务端在写入前校验；不匹配的引用**直接丢弃**（不阻断卡片、不重试）。**空串与纯空白不算有效引用**（数学上它们是任意字符串的子串），走同一条丢弃路径。
2. **提交通道 = 工具**：点评经工具提交（只写 `feedback` 字段）。工具集里**没有任何工具能写 `draft`**。
   > 边界一句话：**AI 能写它自己的产出，不能写用户的产出。**

**维度数上限 = 常量 `MAX_FEEDBACK_DIMENSIONS`**（唯一出处；工具说明由该常量插值生成，禁止复述数字）。

**为什么维度由 AI 提炼而不是固定清单**：固定清单是为「跨练习统计」提前建结构——那个需求未成立（YAGNI）；维度以文本快照留在卡里，不建 schema。

## 5. AI 边界：结构级与 prompt 级

| 层 | 约束 | 强度 |
| :--- | :--- | :--- |
| **工具面** | 练习工作区只注册**两个只读工具**（读范文 / 读稿件）与**一个提交点评工具**；小说工具与**提案工具一律不注册** | **结构性**（靠注册过滤，不靠提示词） |
| **稿件写入** | 工具面没有写稿工具 ⇒ AI 改不了用户稿 | **结构性** |
| **自由对话** | 聊天里**不禁止**出现示范句（问答式是产品四大原则之一：「这句为什么好？」） | **prompt 级**（必须在文档里写明它不是结构级保证） |

**点评与聊天是两条路径**：点评走结构化工具产出（卡片），自由问答走普通对话；两者落在**同一个工作区会话**里。点评触发 = 一条真实的用户消息（文案如「请点评我的仿写稿」）——透明、可回溯，不引入隐藏语义。

## 6. 上下文注入

触发点评时，客户端**只发** `context.practice_sample_id`；服务端**现读**数据库展开本轮注入（与「推演节点只发布尔、服务端现读 `project.json`」同款）：

| 注入项 | 说明 |
| :--- | :--- |
| 样本 id | 点评对象（正文靠只读工具分页拉取） |
| 目标名 + `observation` | 用户自己的观察，短文本；未写则不给该行 |

**注入只给事实**：「必须提交点评卡」这类**指令语义唯一出处 = 练习内核提示词常量**（agent 包 `PRACTICE_KERNEL_PROMPT`）——注入段不复述，否则 = 第二事实源。

**刻意不注入范文与稿件全文**：它们走工具分页读取（受单条工具结果上限与续读提示保护），避免每轮上下文膨胀——与小说侧「聚焦章只注入标题 + 摘要 + 节选、正文按需拉取」同一口径。**不接受客户端传入的观察文本**（否则是任意上下文注入）。

## 7. 不变式汇总

1. 练习数据只活在**练习工作区**的专属表里；不写小说语义的表，不进回收站（物理删）。
2. 范文快照不可变；用户稿只有用户能写；点评只由提交工具写。
3. 点评卡的引用必须能在范文或稿件里逐字找到，否则丢弃。
4. 练习工作区不注册小说工具与提案工具（结构性）。
5. 触发点评的注入由服务端现读展开，客户端只发 id。
6. 点评留痕在会话历史里（用户可见那条消息），卡片本身从数据库读（刷新后仍在）。
