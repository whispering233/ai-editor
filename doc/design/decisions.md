## 决策 1：节点即大纲（统一模型）

大纲树与剧情探索的图状结构共享同一数据中心——**所有节点挂在大纲树上，不存在游离节点**（决策 19）；画布上的剧情连线是关系数据 `plot_edge`（决策 10），不是独立存储。大纲视图与画布视图是**同一数据的两种投影**，不是需同步的两份数据：树上的拖拽重排自动反映到图，图上的连线查询天然复用关系体系。

## 决策 2：通用关系表

**不按实体类型分表**，用一张 `relation_records` 统一管理所有跨实体关系（人物↔设定↔地点↔大纲节点↔事件等，含 `plot_edge` 剧情连线）。新增关系类型只需扩展常量，不需要改表结构；AI 分析时一次查询拿到全图，从任意实体出发查「所有关联」是一个查询。Delta 不在此表——独立存 `delta_records`（决策 3）。

## 决策 3：Delta 变更追踪

人物/设定的属性是演化中的（主角黑化、战力从 100 涨到 850），**不采用版本快照**，采用事件驱动 Delta：大纲节点记录自己**引发了什么变化**。到达任意节点的状态 = 初始值 + 根到该节点路径上所有已确认 Delta 的累积。Delta 存独立 `delta_records` 表，不侵入大纲 JSON 结构，因此也无法表达「树外」的状态（决策 9 只沿父链累积）。

## 决策 4：双轮驱动（人物 ↔ 剧情）

人物系统与剧情探索**不存在主从关系**，两个方向并行、互相喂养：性格决定剧情走向，场景需要角色补位。用户可从任何方向启动，另一方自动响应（画布加场景 → AI 分析缺什么角色；新增角色 → AI 提示可出现在哪些已规划节点）。

## 决策 5：大纲用 JSON，实体用 SQLite

存储双轨制，**不强行统一**：大纲树是天然树形结构，用 JSON 文件（`outline.json`）整树读写、无需拼接；实体/关系/Delta 需要结构化查询与关联追踪，用 SQLite（`data.db`）。两者格式需求天然不同，统一反而增加复杂度。

## 决策 6：分层上下文策略

**不把整个世界塞进 prompt**。四级分层：系统指令（固定角色与行为规范）→ 聚焦上下文（当前视图实体 + 紧邻关系）→ 扩展上下文（AI 通过工具调用按需拉取）→ 对话历史（滑动窗口 + 超限压缩摘要）。预算计算优先采用最近一次成功响应的真实 usage，裁剪/重排历史后必须重置 usage 基线，否则预算漂移。

## 决策 7：提示词三层注入

最终 Prompt = **内核提示词**（代码固定，`agent/prompts.ts`）+ **项目设定**（AGENTS.md，决策 41 取代原 project.json `prompt` 字段）+ **临时指令**（聊天框即时输入，不持久化）。三层编辑者与持久化不同，注入逻辑保持分层，不搞双通道漂移。

## 决策 8：单命令 + 单进程部署

用户工作流：**全局安装 → 进入创作目录 → `ai-editor` 一条命令 → 浏览器完成所有操作**，无 CLI 子命令。单进程 Hono 同时服务 `/api/v1` 与 SPA 静态文件（不需要 Nginx/反向代理）。代码装 node_modules、数据在用户项目目录，物理隔离。启动时目录已有 project.json 自动打开；**无则待命不初始化**（创建只在 create 路由发生）。端口规则/书架模式等细节见 architecture.md。

## 决策 9：Delta 只沿大纲树父链累积（含推演语义）

状态计算 `computeState` **只沿大纲树父链**（根 → 目标节点）累积已确认 Delta——树路径唯一，结果确定可复现；节点间按树路径序、节点内按 `order` 双层排序。`op=update` 校验 from 失败时**跳过该 change 并在 conflicts 中标注**（不返回 409——手动编辑实体 data 不产生 Delta 属正常行为）。`plot_edge` 连线不参与状态计算。**AI 推演是只读路径计算 + 提案生成器**，状态变化不落库、以提案形式呈现，用户确认后才写入——推演与事实分离，防止 AI 假设污染创作数据。

## 决策 11：outline.json 原子写

大纲整树保存用「写临时文件 → fsync → rename 覆盖」的**原子写**，不允许直接覆盖写。大纲是核心创作资产，原子写保证任意时刻磁盘上要么是旧文件要么是新文件（崩溃/断电不损坏）。project.json 同款原子写。

## 决策 12：软删 + 回收站

删除走**软删 + 回收站**：实体/关系/Delta 标 `deleted_at`、大纲节点标 `deleted`，**级联一并软删**（purge 才物理清除），常规查询默认过滤，restore 级联还原。**手动删关系 = 物理删**（关系轻量可重建，不占回收站）；关系/Delta 可见性联动端点软删状态（任一端点软删即不可见）。restore 节点校验祖先链——存在软删祖先返回 409 `OUTLINE_ANCESTOR_DELETED`。软删/还原更新 `updated_at`，保证提案快照比对（决策 14）语义统一。

## 决策 13：schema 演进

以 data.db 的 `PRAGMA user_version` 为准**三态分流**：匹配 → 正常打开；**高于程序版本（未来版本）→ 拒绝打开**（数据不动，防降级损坏）；低于 → 旧版本，**有迁移路径则按序增量迁移**（每迁移一事务、失败回滚、时间戳快照），**无迁移路径才删库重建兜底**（备份 `.bak` 含 data.db，重建同步重置 outline.json）。`project.json`/`outline.json` 的 `schema_version` 只管 JSON 结构，不参与重建判定。

## 决策 14：提案生命周期 —— 仅内存

提案（AI 写操作的确认对象）**仅存服务端内存**，随 SSE 事件推送，不落盘；TTL 10 分钟 + 条数上限，超期自动清除。确认时服务端**重新校验**引用（存在性 + `updated_at` 快照比对），失败返回 409 `PROPOSAL_STALE`，proposal_id 不存在返回 404。提案绑定项目（project_id），切换项目时清空全部内存提案并强制结束在途 SSE/agent 循环。

## 决策 15：agent 循环终止与失败处理

agent 循环三重硬性终止：**max 8 轮 / 单轮 120s（含重试退避与工具执行）/ token 预算**。工具执行失败以结构化文本喂回 LLM 自纠；超限发 `error` 事件终止，失败对用户可见不静默。模型调用错误分类：配额/计费类（402、`insufficient_quota`）快速失败不重试，瞬时类（429/5xx/超时）指数退避重试，**abort 永不重试**。`finish_reason=length`（截断）时不执行任何 tool_call——流式拼接的参数可能静默不完整，标记错误让模型重发。

## 决策 17：安全基线

服务默认绑定 `127.0.0.1`，不对外网开放。中间件对**全部请求（含读）**校验来源 host ∈ {`127.0.0.1`, `localhost`, `::1`}（Origin 缺失时退化为校验 Host；不校验端口——端口自动 +1 与 dev proxy 依赖此规则），防 CSRF / DNS rebinding。DeepSeek key 走环境变量或用户级配置（`~/.ai-editor/config.json`），**绝不进项目文件**。项目路径校验 resolve 规范化 + 防符号链接逃逸。

## 决策 19：大纲严格三层，无游离节点

大纲树固定三层 **volume（卷）→ chapter（章）→ scene（场景）**，**不存在游离节点**（无 `orphan_nodes` 机制）：创建必须显式指定 `parent_id`，scene 只能挂 chapter。游离节点制造「树外状态」的语义裂缝——状态计算、软删级联、提案快照都要为它开特例。节点带 `updated_at` 版本戳（支撑决策 14 快照比对），顶层带 `schema_version`。

## 决策 22：三栏工作台布局与会话归属项目模型

UI 为**三栏工作台**：左（产品标识 + 书架树 + 设置/主题）/ 中（InfoBar + 7 tab：概览|大纲|实体关系|伏笔|时间轴|参考资料|回收站 + 内容区）/ 右（ChatPanel 常驻，`<1024px` 折叠为抽屉）。**`#/chat` 独立页移除**——聊天常驻右栏，跨页「问 AI」注入当前会话 focus context，不跳页；**会话归属项目**（一项目一创作语境，`chat_messages` 按 project_id 隔离），切项目重置会话。F7 修订：三栏可拖拽调宽 + 收起/展开，宽度与状态存 localStorage（纯展示层，不进数据文件）。

## 决策 23：大纲节点结构化信息（麦基《故事》字段集）

大纲节点长期只有 title/summary 自由文本，作者无法挂载结构化信息。outline.json 节点新增可选 `data` 字段，按层级 schema 校验：scene = `goal`/`conflict_levels`（麦基冲突三层次）/`value_from`/`value_to`（价值转向——「没有不转折的场景」）；chapter = `reversal`/`climax_scene`；volume = `climax_scene`/`inciting_scene`。字段集宁少勿多（每层 1-3 字段），是 AI 做小说理论分析的结构化输入基础。**编辑 data 不自动生成 Delta**（决策 9 修订语义），详情页 `#/outline/:nodeId` 承载展示与编辑。

## 决策 26：时间轴（事件实体 + timepoint 实体化）

时间序与结构序是**两种正交的叙事维度**——大纲树表达阅读/结构顺序，时间轴表达事件发生顺序（倒叙、多时间线只能靠独立事件序表达）。事件是第 5 种实体类型 `event`，复用实体体系（泛型 CRUD/回收站/软删/关系，零新增机制成本）；**拖拽 `sort_order` 为权威**，时间标签不解析不排序。G2 修订：时间标签剥离为独立实体 **timepoint**（第 6 种实体），以 `occurs_at` 关系挂载事件（1:n）——「先定义时间点、再挂载事件」，双独立线性序（组间/组内正交），跨组拖拽即改挂载。

## 决策 34：LLM 引擎换核 —— 引入 pi-ai

llm 包**对外契约不变**（`chatStream`/`LLMStreamEvent`/`LLMError`），内部从手写 fetch/SSE 换为 `@earendil-works/pi-ai`（providers/deepseek 子路径注册，勿手写 SSE/流式累积）。单一**单向 adapter** 转换（LLMMessage→pi-ai Context / 事件转发 / usage 口径 / 错误归一化），上层（agent/server/shared/前端）零改动——标准防腐层：pi-ai 快速演进被隔离在 llm 包内。保留 `retry.ts`（决策 15 语义）、`token.ts`（决策 6 预算）、AbortSignal 四层穿透（决策 16）；新增 `getAvailableModels` 模型目录。

## 决策 41：项目规则文件 AGENTS.md

项目目录 **AGENTS.md** 是**唯一**持久化上下文通道（取代 project.json `prompt` 字段——打开项目时 prompt 存在且无 AGENTS.md 则自动迁移，一次迁移后 prompt 不再使用），注入 system「## 项目设定」段。设置页直编 AGENTS.md（GET/PUT `/project/agents`，原子写）+ 用户可在文件管理器中直接编辑（web 读取 mtime 检测外部修改）；聊天框消息即临时指令层（决策 7）。AGENTS.md 是社区广泛接受的「项目规则」惯例，可见、可版本化，prompt 字段藏于 project.json 不可见不可控。

## 决策 49：db 查询层引入 drizzle-orm

db 包查询层引入 drizzle-orm（查询构建器 + 行类型推断）提升开发体验，**但只做查询层**，四件事不变：① 驱动仍是 better-sqlite3 同步连接，事务（决策 16 先 DB 后 JSON 的同步语义）与 WAL 持久化原样；② **不引入 drizzle-kit**——迁移管线维持自建 `PRAGMA user_version` 三态分流（决策 13：E4 防降级 / E5 增量迁移），表结构声明收敛到 db 包 `tables.ts`（sqliteTable 定义 + 手写 DDL 常量同文件，schema.test.ts 断言锁对齐）；③ `data` JSON 列**保持 text 模式 + rowToEntityRow 防御解析**（drizzle `mode:'json'` 对坏 JSON 直接抛错，破坏「单条坏行不打挂整表查询」的防御）；④ shared 的 API 契约类型（EntityRow 等）不动、类型不反向流入 shared（shared 是依赖树最底层）。查询模块函数签名保持 `(db: Db)`，内部经 `queryDb` 辅助包装 drizzle 实例（WeakMap 缓存）——调用方零改动，逐模块渐进替换（混合风格：简单 CRUD 用 builder，复杂排序/跨表 UPDATE 用 `sql` 模板逃生舱，不强行翻译）。
