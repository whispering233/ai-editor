# EntityList 实体列表原型

## 路由与数据

- 路由：`#/entities/:type?`（type ∈ character|setting|location|hook，缺省 character；tab 切换即改 hash）
- 数据：`GET /api/v1/entity/:type?q=&offset=&limit=&sort=&order=`
- 新建：`POST /api/v1/entity/:type`

## 布局线框

```
┌──────────────────────────────────────────────────────────┐
│ [人物] [设定] [地点] [伏笔]        [🔍 搜索名称…]  [+ 新建]  │
├──────────────────────────────────────────────────────────┤
│ 排序: [更新时间 ▾]                        共 24 个         │
├──────────────────────────────────────────────────────────┤
│ 名称          角色       状态      更新时间                 │
│ 张三          主角       活跃      8-01                    │
│ 李四          配角       退场      7-28                    │
│ …                                                        │
├──────────────────────────────────────────────────────────┤
│               ‹ 上一页   第 2 / 3 页   下一页 ›             │
└──────────────────────────────────────────────────────────┘
```

## 信息层级

列表接口返回 `EntitySummary`（不含完整 data），各类型摘要列取自 `summary`：

| 列 | character | setting | location | hook |
|----|-----------|---------|----------|------|
| 名称 | `name` | `name` | `name` | `name` |
| 摘要列 1 | `summary.role` | `summary.category` | `summary.type` | `summary.status` |
| 摘要列 2 | `summary.status` | — | — | `summary.payoff_timing` |
| 时间 | `updatedAt`（相对时间） | 同左 | 同左 | 同左 |

分页元数据：`total` / `offset` / `limit`。

## 关键交互

- **Tab 切换**：改 hash（`#/entities/location`）；MVP 切换时重置搜索与分页（保持简单）。
- **搜索**：`q` 输入防抖 300ms 发请求；空关键词跳过请求直接显示列表。
- **排序**：`sort`（name / created_at / updated_at）× `order`（asc / desc）下拉。
- **分页**：limit 固定 20（MVP）；前端按页码换算 `offset` 提交，用返回的 `total` 算总页数。
- **新建**：对话框（`name` 必填 + 该类型首字段，如 character 的 `role`）→ `POST /entity/:type` → 成功跳详情页。
- **行点击** → `#/entities/:type/:id`。

## 状态

- **空态（两种，文案区分）**：
  - 该类型无任何实体：「还没有人物，新建一个」+ [新建]。
  - 搜索无结果：「没有匹配「xxx」的实体」+ [清空搜索]。
- **加载态**：列表骨架。
- **错误态**：列表请求失败 → 区块内重试；`VALIDATION_ERROR`（如 limit 超 200）→ toast。

# 关联 Tab（实体关系总览，U8 增补）

## 路由与数据

- 路由：`#/entities/relations`（四类类型 tab 之后的第 5 个 tab；main.tsx 实体分支先拦截 `relations` 段，不参与类型归一化）
- 数据：`GET /api/v1/relation?depth=1`（`ListRelationsRes.relations`，双向紧邻，联表填充端点名称）；过滤参数 `source_type`/`target_type`/`relation_type`（endpoints.md）
- 建立：`POST /api/v1/relation`；删除：`DELETE /api/v1/relation/:id`（物理删）

## 布局线框

```
┌──────────────────────────────────────────────────────────────┐
│ [人物][设定][地点][伏笔][关联]   [端点类型▾][关系类型▾] [+ 建立关联] │
├──────────────────────────────────────────────────────────────┤
│ 源                    关系                 目标              │
│ 张三 (人物)        师徒 →      李四 (人物)           [删除]   │
│ 第3章·灵根测试      出现于 ←    张三 (人物)           [删除]   │
│ …                                                            │
└──────────────────────────────────────────────────────────────┘
```

## 信息层级

| 元素 | 内容 |
|------|------|
| 行 | `sourceName`（+端点类型徽标）→ 关系类型标签（`relationTypeLabel`，含方向箭头）→ `targetName`（+端点类型徽标）→ [删除] |
| 端点类型徽标 | `source_type`/`target_type`：character/setting/location/hook/outline_node → 人物/设定/地点/伏笔/大纲节点 |
| 方向 | 按存储方向展示（源 → 目标）；depth=1 返回即存储方向，本视图不镜像反转 |

## 关键交互

- **Tab 切换**：切回四类 tab 恢复原列表视图；切进关联 tab 重置过滤（与现有「MVP 切换时重置」约定一致）。
- **过滤**：端点类型下拉（全部/人物/设定/地点/伏笔/大纲节点）+ 关系类型下拉（全部/`RELATION_TYPES`）；名称搜索在输入框**前端过滤**（MVP 关系量级小，服务端 `q` 不支持名称模糊）。
- **建立关联**：关联 tab 下原「+ 新建」按钮变「+ 建立关联」→ 对话框（复用详情页 `CreateRelationDialog`，抽为共用组件，列表模式暴露源实体选择）：
  1. 源实体：类型下拉（默认 character）+ 实体下拉
  2. 目标实体：类型下拉 + 实体下拉（含大纲节点选项，与详情页一致）
  3. 关系类型下拉 + 方向说明「源 → 目标」
  4. `POST /relation`；`RELATION_EXISTS` → toast「这条关系已经存在」；成功 → toast「已建立关系」+ 刷新列表
- **删除**：行内 [删除] → 确认框（物理删除不可恢复，可重新建立，与详情页文案一致）→ `DELETE /relation/:id` → toast「已删除关系」+ 刷新。
- **跳详情**：端点名（源/目标）点击 → `#/entities/:type/:id`。

## 状态

- **空态（两种，文案区分）**：无任何关系「还没有关联，建立一条」+ [建立关联]；过滤无结果「没有匹配的关联」+ [清空过滤]。
- **加载态**：列表骨架。
- **错误态**：请求失败 → 区块内重试。
