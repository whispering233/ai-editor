# 概览页原型（中栏「概览」tab；无项目时为引导页）

> 2026-08 修订：原 Dashboard 页拆分为两部分——**书架形态移入左栏 Sidebar 书架树**（layout.md §2.3），**概览形态成为中栏默认 tab**（`#/`）；无项目时 `#/` 显示引导页。

## 路由与数据

- 路由：`#/`（默认落地页，中栏「概览」tab）
- **两种形态**：
  - **引导形态（无项目打开，loadError=NO_PROJECT_OPEN）**：中栏显示创建/打开引导；数据 `GET /api/v1/project/list` → `{ rootPath, books: [...] }`——书架树由左栏 Sidebar 展示，引导卡内**同样列出书籍**（S13.4：有书可直接打开，见下节）；`rootPath` 供新建表单 `buildBookPath` 使用
  - **概览形态（项目已打开）**：以下数据（并行请求，全部失败不阻塞页面渲染）：

| 用途 | 端点 |
|------|------|
| 项目信息 | `GET /api/v1/project/config` |
| 四类要素统计 | `GET /api/v1/entity/character`、`/setting`、`/location`、`/hook`（各取 `total`，limit=1 即可） |
| 大纲概览 | `GET /api/v1/outline`（递归统计卷/章/场景数） |
| 最近会话 | `GET /api/v1/chat/sessions`（取前 5 条） |

## 引导形态（无项目）

> 形态判定：`config === null && !configLoading`（loadError=NO_PROJECT_OPEN 或网络失败）。
> S13.4 修复：引导卡**按书架状态分派**——书架有书时卡内直接列出书籍（此前无条件显示「还没有书，先创建一本」，books 列表只在左栏 Sidebar 展示，有书未打开时文案误导）。

### 有书（bookshelf.books.length > 0）

```
┌───────────────────────────────────────────────────────────────┐
│ （中栏信息条显示「书架」）                                        │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │                书架里有书，打开即可写作                       │ │
│ │           选择一本书打开，或新建一本                          │ │
│ │ ┌───────────────────────────────────────────────────────┐ │ │
│ │ │ 📖 我的小说                               2 小时前       │ │
│ │ │ 📖 修仙笔记                                昨天          │ │
│ │ └───────────────────────────────────────────────────────┘ │ │
│ │ （打开失败 → 列表下方行内错误，describeOpenError 文案）        │ │
│ │ ───────────────────────────────────────────────────────── │ │
│ │ [新建一本…]（折叠：书名输入 + 新建，次级入口）                  │ │
│ │ [打开其他路径…]（折叠：路径输入 + 打开，S1.4 保留）             │ │
│ └───────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

- 书籍行：BookOpen 图标 + 书名 + 相对时间（`formatRelativeTime`），整行可点（`hover:bg-muted`）→ `openProjectAt(book.path)` 打开（store 刷新 config/outline → 本页切概览形态）；打开失败 → 行内错误（`describeOpenError` 映射，同「打开其他路径」表单模式）。
- 新建书籍保留为**次级折叠入口**（不删创建能力）；「打开其他路径…」折叠保留。

### 空书架（bookshelf 加载完成且 books.length === 0）

```
┌───────────────────────────────────────────────────────────────┐
│ （中栏信息条显示「书架」）                                        │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │                   还没有书，先创建一本                        │ │
│ │                                                           │ │
│ │ 书名: [______________________]        [新建]               │ │
│ │ （创建于 创作根/books/<书名>/）                              │ │
│ │                                                           │ │
│ │ [打开其他路径…]（折叠：路径输入 + 打开，S1.4 保留）            │ │
│ └───────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

- 「还没有书，先创建一本」文案**仅此分支**出现；新建表单为主操作（原样保留）。
- 新建成功 → 左栏书架刷新 + 打开新书（现状不变）。

### 加载中 / 加载失败

- **加载中**（bookshelf === null && bookshelfLoading）：引导卡内骨架（标题占位 + 两行列表占位）——防「还没有书」误闪（打开页面瞬间书架未就绪即误显空态，是本 bug 的加载态变体）。
- **加载失败**（bookshelfError）：引导卡**上方**错误块 + [重试]（保留）；卡内显示中性占位「书架加载失败，重试后可查看书籍或新建」（不显示「还没有书」）；「打开其他路径…」不依赖书架，仍可用。

## 信息层级

| 区块 | 展示 | API 字段 |
|------|------|---------|
| 项目信息 | 名称、语言、当前位置、提示词（截断 2 行） | `name` / `language` / `currentPosition` / `prompt` |
| 创作要素 | 四张计数卡（数字 + 类型名） | `GET /entity/:type` → `total` |
| 大纲概览 | 卷/章/场景计数、最近更新 | `GET /outline` → `children` 递归统计（无现成汇总字段，前端自算）；最近更新 = 树中最大 `updatedAt` |
| 最近会话 | 摘要、消息数、相对时间 | `sessions[].{ lastMessage, messageCount, updatedAt }` |

## 关键交互状态

- **空态（新项目）**：整页引导卡「项目还是空的」→ 主按钮 [先搭大纲]（跳 `#/outline`）、次按钮 [和 AI 聊聊设定]（注入右栏新会话）。
- **回到书架**：不再需要独立按钮——左栏书架树始终可见，点击其他书即切换项目（S1.6 的「回到书架」入口由左栏书架替代）。
- **加载态**：各区块骨架。
- **错误态**：单区块失败 → 区块内「加载失败 [重试]」；全量失败 → 全局错误横幅。本页理论上不会出现业务错误码（项目已打开）。
- **操作流**：点会话行 → 注入右栏并恢复该会话（chat store 设置 `session_id`）；点统计卡 → 跳 `#/entities/:type`；点「去大纲」→ `#/outline` 并定位当前位置节点。

## 与 AppShell / 全局布局的关系

- 引导形态下信息条项目名显示「**书架**」（layout.md §2.1）；左栏书架树照常可操作（创建/打开项目）。
- 设置页（`#/settings`）与项目无关，无项目时照常可达（左栏底部入口）。
- 未来扩展（不实现，backlog 候选）：list 返回每本书统计（章节数/进度/字数/最近位置）、真实活跃时间（`updatedAt` 语义偏差，需服务端配合）、删除/重命名书籍端点。
